# sale_bot Windows 테스트

이 폴더는 **Windows용 런처/메뉴/진단 도구만** 보관합니다. 실제 sale_bot Python 코드는 상위 저장소의 `src/`를 그대로 사용합니다.

따라서 예전처럼 Windows 복사본의 `src/`와 Ubuntu용 `src/`를 따로 맞출 필요가 없습니다.

## 시작

저장소 ZIP 전체를 받은 뒤 이 폴더의:

```text
SALE_TEST.bat
```

을 더블클릭합니다.

메뉴:

```text
1. 최초 설치
2. 코드 테스트
3. 중고마켓 실제 검색 1회
4. 계속 실행
5. 초기 seed/런타임 설정 열기 (config.yaml)
6. 텔레그램/디스코드 알림 설정 열기 (.env)
7. Windows 테스트 DB 완전 초기화
8. 당근 지역/검색 샘플 진단
9. 당근 '전체' 지역 전수 해석 검증
0. 종료
```

## 권장 순서

처음 받은 ZIP이라면:

```text
1 → 2 → 6 → 4
```

- `1`: 이 폴더에 `.venv`를 만들고 **상위 루트 프로젝트를 editable 설치**합니다.
- `2`: 루트 `src/`와 `tests/`를 그대로 검사합니다.
- `6`: Telegram Bot Token / Chat ID를 입력합니다.
- `4`: 봇을 계속 실행합니다.

실행 뒤 감시 슬롯은 Telegram에서:

```text
/menu
```

를 입력하고 버튼으로 추가/수정/삭제하는 것을 권장합니다.

## config.yaml은 무엇인가요?

`config.yaml`은 이제 감시 슬롯의 주 관리화면이 아닙니다.

주 용도:

```yaml
poll_interval_seconds: 300
request_timeout_seconds: 20
watches: []
```

- 목표 검색주기
- request timeout
- 완전히 새 DB를 만들 때 선택적으로 넣을 최초 seed

운영 중 슬롯 정보는 SQLite DB가 기준입니다.

## 슬롯 삭제

Telegram에서 슬롯을 완전 삭제하면 해당 슬롯의:

- 감시 설정
- 매물 상태
- 가격변동 이력
- 마지막 알림 가격/횟수
- pending 알림
- bootstrap/search 상태

가 함께 삭제됩니다.

다시 같은 키워드를 추가하면 새 슬롯처럼 시작합니다.

메뉴 `7`은 **Windows 테스트 DB 전체**를 지우는 기능이므로 모든 테스트 슬롯을 처음부터 다시 시작하고 싶을 때만 사용하세요.

## 당근 지역

Telegram에서 다음처럼 입력할 수 있습니다.

```text
청주시
청주시 청원구
청주시 청원구 오창읍
대전시 유성구
대전시 유성구 봉명동
```

시/군/구까지만 입력하면 해당 행정구역 전체로 검증합니다. 없는 지역이나 동명이의 애매한 지역은 저장 전에 오류가 납니다.

메뉴 `8`은 현재 슬롯으로 소수 지역의 실제 검색을 확인하는 진단입니다.

메뉴 `9`는 넓은 지역에서 발견한 모든 하위 지역이 당근 region ID로 해석되는지 확인합니다. 매물/가격/알림 DB는 변경하지 않습니다.

## 검색주기

기본 목표는 5분입니다. 다만 당근의 넓은 지역 × 많은 키워드는 요청량이 크므로 요청을 약 1.2초 이상 간격으로 분산합니다.

작업량이 5분 안에 끝나지 않으면 다음 순환을 바로 이어가며, Telegram `/status`에서 최근 실제 검색시간과 오류 수를 볼 수 있습니다.

## 알림 정책

예: 목표 최대가격 100만원

```text
120만원 → 알림 없음
 99만원 → 알림
 99만원 → 반복 알림 없음
 80만원 → 가격 하락 알림
 90만원 → 가격 상승 알림 없음
 60만원 → 가격 하락 알림
```

첫 실행에 이미 존재하던 매물은 알림하지 않고 기준선으로 저장합니다.

## 필요한 환경변수

`.env`:

```text
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=

# 선택: Discord 알림만
DISCORD_WEBHOOK_URL=
```

설정 관리는 Telegram으로 통일하고 Discord는 Webhook 알림만 지원합니다.
